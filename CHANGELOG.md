# Changelog

All notable changes to the Enterprise Bootstrap Theme project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

This file is maintained by coding agents and updated at the end of each session when
user-visible changes are made. Entries are generated from `agentknowledge/history.jsonl`
and the git log. For the complete machine-readable history, see `agentknowledge/history.jsonl`.

## [Unreleased]

### Changed
- **BREAKING: a second `createMarkdownRenderer` naming a different `highlight` or `math` now throws** (ADR-216). `configureMarked` ran once per page behind `let configured = false`, a latch keyed on nothing, so the **first** renderer created in a page decided those two options for every later one. A second caller asking for `math: false` was handed a renderer with KaTeX still wired in and told nothing — ADR-200's discriminator exactly: a request the caller named got neither the effect nor an error. `marked.use()` is global and already applied, so the call cannot be honoured; it is refused by name instead. The latch is keyed on the `marked` instance now, which also means a reloaded `marked` is reconfigured. Every option other than `highlight` and `math` is read per render and needs no agreement. Nothing in this repository trips it: HelpDrawer, DocViewer and both studio demos call with the defaults.
- **`MarkdownRendererOptions.className` now does what its doc comment says.** It has carried "Additional CSS class for the rendered wrapper" since it was added and nothing in the component ever read it, so a caller passing it got the documented type and no class. `render()` applies it to the target; `toHtml()` returns a string and has no wrapper to carry it.
- **BREAKING: `sampleFor` throws for a data shape with no sample** (runtime conformance). It ended `(SAMPLES[shape] ?? SAMPLES.record)()`. `DataShape` is a closed vocabulary of ten, so a missing entry is a gap in that table and not an input a caller can send — and the substitution meant a host exercising a `geo` slot was handed `{ id, name }` and told nothing.
- **`CommentOverlay`'s container contract is documented by its test now, and it is the opposite of what the test's name claimed.** `createCommentOverlay(containerId, options)` resolves `containerId` and then **overwrites** `options.container` with what it found, so a container passed in the options is ignored whenever the factory is used.
- **DiagramEngine's spatial containment feature is unreachable** (DEBT-DE-1, new). `ShapeDefinition.isContainer` is declared and read in three places and **no stencil in the repository sets it**, so dragging a shape onto a browser frame, phone frame or page frame does nothing. The machinery is correct — adding `isContainer: true` to one stencil makes the drop work — so the gap is data, and which shapes are containers is a product decision the entry does not make.

- **The instrument that counts tests which cannot fail was over-counting by 32 and hiding one** (DEBT-TEST-1b 204 → 117, ADR-216). Two rules in `isVacuous` read the TEXT where the VALUE was meant. The exemption for a DOM query carries the comment THE SUBJECT DECIDES, NOT THE MATCHER and then tested the characters inside `expect(...)`, so `expect(root.querySelector(".x")).toBeTruthy()` was exempt while `const x = root.querySelector(".x"); expect(x).toBeTruthy();` was counted — the identical claim, decided by whether the author used a const. And a lookup was exempt under **either** existence matcher, though every member of the family returns `null` and `expect(null).toBeDefined()` passes. The correction runs both ways: it added `formdialog :: withDefaultSize_UsesMdSize`, which the exemption had been hiding.
- **The `existence` bucket is empty, 85 → 0**, and the title question found a product defect in most files it reached. `datagrid :: getBodyRows()` returned **four of five rows** and had no caller; `helptooltip`'s topic is not in the popup at all; `markdownrenderer`'s `className` went nowhere; `cronpicker`, `symbolpicker` and `diagramengine` each named a fact nothing read.
- **An assertion that never RUNS is a different fault from one that cannot fail, and it has a number now** (`guardedAssertions`, ADR-216). Whether a guard ever opens cannot be read off the text, so the sweep puts a must-fail assertion inside each guarded body and runs the suite — a block whose guards never open stays green. **81 sites in 71 blocks; two never opened.** `applauncher :: OnSelect_FiresCallback` queried `.applauncher-app-card`, a class the component has never written, so its **only** assertion never ran and AppLauncher's `onSelect` had never been exercised. `spinemap :: multipleXssVectors_SafeRendering` looped over `[href]` elements that do not exist, so a third injection vector read as checked and was skipped. Both fixed; the sweep now reports 0 of 71.
- **`spinemap :: onNodeClick` had three independent mismatches in one block.** It queried `[data-node-id]` where the groups carry `data-id`, dispatched `pointerdown`/`pointerup` where the component listens for `click`, and then asserted `expect(map).toBeDefined()` under a comment saying the callback "may or may not be called". It was never called once. The callback works; only the test was broken.
- **`.not.toThrow()` is the wrong assertion for an idempotence claim, and the last bucket's "near zero yield" was a prediction.** Deleting `if (this.destroyed) { return; }` from `BannerBar.destroy()` **entirely** leaves `Destroy_CalledTwice_IsIdempotent` green — a second call would then fire `onClose` twice, and the block named for idempotence could not see it. 107 members are that shape, so DEBT-TEST-1b stays open with a demonstrated yield rather than a guess.

- **The test-shape bucket named "name states a change" never read a name** (DEBT-TEST-1b 236 → 223, ADR-215). `shapeOf` returned `namesAChange` for every `.not.toThrow()` block that was neither idempotent nor dependency-withheld, whatever its title said — so **21 of its 35 members had titles stating no effect at all**, `importInvalidJSON_DoesNotCrash` and `rapidFire100Toasts_NoExceptions` among them. The doc comment above the code had described the intended rule for two days and the code never implemented it. A count named for one population while measuring another, inside the instrument built to stop exactly that.
- **The case pinning that bucket could not fail.** It asserted `setFilters_UpdatesFilterState` lands in `namesAChange`, which held for any `.not.toThrow()` body. It now asserts both directions, and `robustnessOnly` and `positiveControl` are separate shapes with their own pinned rules.
- **Each new rule over-claimed once, both in the way its predecessor already had.** Scoping the accept/refuse pairing to the `describe` claimed `diagramengine-core :: resize does not throw`, whose block refuses a bad *container* — a refusal about `createDiagramEngine`, not about `resize`, which is ADR-203's per-file mistake one level finer. The callee now has to match. Then `treegrid :: deeplyNestedNodes_RendersWithoutCrash` paired correctly on `createTreeGrid` and still was not a control, because the two accept and refuse on different dimensions. **A survival title now outranks a pairing: the name is the fact and the pairing is the hypothesis.**
- **All 14 real members rewritten, each mutation-proven.** `setDrawShape` draws and reads `presentation.shape` back; `setZoom` reads `scale(4)` off the lens clone; `refresh_ReRendersTree` asserts the same labels come back on **new** elements with the old ones detached; `Destroy_CleanUpHandlers` watches the `onClick` spy that was already in the options and never looked at; `destroy removes all listeners` pairs every `addEventListener` with a remove, and names the two leaked types when mutated; `updatesEngineOptions` drives a trigger session and proves the debounce moved from 100 ms to 300.
- **Two of the 14 were never defects, and they are different false positives.** `wiring :: accepts a binding naming a registered transform` sits directly under its throwing sibling and is the accept half of a pair — the instrument now recognises that on its own merits rather than through the withheld-globals proxy that only ever found the six in `*.nofallback.test.ts`. The DynamicCanvas anchor test carried a real query behind a one-line helper the predicate cannot see, and was strengthened on its merits instead: it now watches `Element.prototype.querySelector` and asserts no call carried the hostile fragment.
- **The `robustnessOnly` bucket emptied too, 21 → 2, and each rewrite asked one question**: what would this method have to do to make the assertion false? When the only answer was "crash", the name's real claim went unchecked. `ribbon :: setActiveTab_InvalidId` now proves the previously active tab is **still** active; `toast :: rapidFire100Toasts` proves five are visible at the cap in order and that dismissing one **promotes the sixth**, so the other 95 are queued rather than dropped; `ribbonbuilder :: importInvalidJSON` finally asserts the `errorSpy` that was already sitting in its body unexamined.
- **The two survivors are a measured jsdom floor, not an oversight.** `diagramengine :: resize` and `zoomToFit with objects` both read `getBoundingClientRect`, which jsdom answers with zeros — a probe confirmed zoom 1 before and after, no `viewBox` at all, and an SVG sized in percentages. **The zoomToFit claim moved to `tests/diagramengine.spec.ts`**, where objects spanning 4000×3000 at 2× have to zoom out to be framed; mutation-proven by deleting the call, which leaves it at 2.
- **The `existence` bucket is not "near zero yield", and nobody had asked it the question** (DEBT-TEST-1b stays open at 204). `shapeOf` splits on the **matcher** first, so a title is only ever read inside the `.not.toThrow()` family — a block named for an effect whose body says `expect(handle).toBeDefined()` lands in `existence` and is never asked whether its title is true. **That is the same defect, one bucket over.** About 25 of the 85 are plainly actionable, including `datagrid :: sort_ByColumn_SortsAscending`, where **nothing checks the order**. Settling the entry here would have rested on a "near zero" prediction carried since 18 October that the first sample contradicted.
- **An assertion inside a condition is a block with no assertion, and no number is recorded for it.** `latexeditor :: symbolCells_HaveAriaLabel` reads `if (cells.length > 0) { expect(...) }`; `testsWithoutAssertion` reads 0 because it counts `expect(` textually. Two confirmed by reading. Quantifying the shape needs an instrument, so the tracker records the two rather than a guess.

- **`JSON.stringify` not throwing is not serialisability.** It returns `undefined` for a function and silently drops one inside an object. One conformance sample was checked that way; all ten must now survive `JSON.parse(JSON.stringify(x))` unchanged, which is what the gate does with them.

### Fixed
- **`RichTextInput.focus()` is correct and jsdom cannot observe it.** The test asserted no throw under a comment reading "in jsdom, focus may not fully work". **Measured:** jsdom will not focus a `contenteditable` div with no `tabindex`, focuses the same div once one is added, and focuses an `<input>` either way. A real browser focuses a contenteditable without one, so adding a tabindex to the *component* to make a test observable would be the test driving the product. The claim is now read where it is observable.
- **Typing `@` in the full demo's rich text input has never shown a mention menu** (DEBT-STI-2, ADR-215). `isSuppressed` read `def.activation.suppressIn.length` unguarded, and `demo/full-demo.html` registered its `mention` and `issue` triggers with the field names of an older API — `precedingChar`, `minLength`, `maxLength`, no `suppressIn`. Reproduced with that exact object: **`TypeError: Cannot read properties of undefined (reading 'length')` on the first keystroke**, raised inside the input listener where no consumer could see it. `initStie` wraps construction in a `try` and the throw happens later, so even that catch never saw it; the demo-page suite passes because it asserts a page loads clean, not that typing into it works.
- **`register()` now fills the documented defaults and refuses an unknown field, naming it.** Every `TriggerActivation` field was *required* in TypeScript, which made this unreachable from TypeScript and from nowhere else — **this library ships to a CDN and is consumed from plain JavaScript**, and `RichTextInput` declares `activation?: Record<string, unknown>` and forwards it unchecked. The fields are optional now, as the README always said they were. Defaulting around a misspelled `minLength` would have left those two demo triggers working and quietly not doing what their author asked for, so an unrecognised key throws instead.
- **This was first written up as a decision to hand back, and it was not one.** The `activation?` type and the README's Default column had both already said the fields were optional. The only thing missing was the code that makes it true.

- **The fleet conformance gate's exemption list reaches zero** (DEBT-DUI-4 3 → 0, ADR-214). **101 of 101 in-scope components migrated, 0 exempt, 24 permanently excluded**, down from 16 exempt on 3 August. The last three blockers were re-read against the files rather than against themselves, and not one survived. **Two of the three migrations needed no change to the component's source.**
- **DiagramEngine's blocker was wrong on both halves, and the first half was a copy.** It read *"Requires a live GraphCanvas handle ... migrate after phase 10 extracts that registry."* `createDiagramEngine(container, options = {})` has **no required option at all**, and the GraphCanvas sentence is GraphMinimap's blocker verbatim — which ADR-206 had already shown to be false. **Phase 10 completed on 3 August** doing the runtime bundle and DynamicCanvas; it never touched the embed registry, and that registry is orthogonal in any case — it lets a *diagram* embed other components, reached only from the consumer-called `loadEmbedPack`. Its own suites have constructed it under jsdom since August. Size was the real deterrent, and size is not a blocker.
- **DynamicFormSwitcher's "design question" offered a choice between something and nothing.** It asked whether to declare one `affords` entry per field type or one for the form. `affords.shape` is a `DataShape`, a closed vocabulary of ten, and **"text", "password" and "url" are HTML input types that are not in it** — so one entry per field type was never expressible. What the component renders is one variant's worth of named values, which is a `record`.
- **MarkdownEditor's factory was missing a keyword, not an entry point.** `createMarkdownEditor(containerId, options)` already existed, already sat on `window`, and is already the documented entry point — `COMPONENT_INDEX.md` names it, seven demo pages call it. It lacked the `export` keyword, which the IIFE bundle strips and **no consumer can observe**. The gate resolves `mod[manifest.factory]`, so a missing keyword made an existing public function invisible to it.
- **Adding that keyword found a defect on the first run.** `scripts/factory-census.mjs` could finally see the factory, and ERR-1 failed immediately: `createMarkdownEditor` **logged and returned `null`** when its container was missing, against a recorded ceiling of zero. Every sibling throws. **It throws now** — a breaking change for any caller that was testing the return for `null`, and the README already documented the non-nullable form.

### Fixed
- **The Markdown editor no longer substitutes a plain textarea for itself** (FALLBACK-15, ADR-214). With `window.Vditor` absent, the editing modes rendered a textarea that carried the caller's markdown, accepted typing, had its own class in the component's SCSS, and **read back through `getValue()`**. An editor with no toolbar, no preview, no shortcuts and no markdown awareness looked like a deliberate minimal mode, and the only signal was a console line the user never sees. The host now shows a visible missing-dependency notice naming vditor and what to load, and `getValue()` and `setValue()` refuse. **A notice declares the failure; a textarea substitutes for the component** — this is CodeEditor's CodeMirror notice and ChartPanel's Chart.js notice, styled to match.
- **The first pass of that fix was the thing the entry describes.** It removed the substitute surface and `getValue`/`setValue` by grepping for `textarea`, and left `focus()`, `enable()`, `disable()` and `setEditable()` **returning normally having done nothing** — the exact shape FALLBACK-11 removed from CodeEditor nine methods at a time. ADR-200's discriminator settles it: a request the caller NAMED is owed either the effect or an error. All four now refuse through one `requireVditor(what)` guard. `showMarkdownEditorModal` also declared `MarkdownEditor | null` and cannot return null, forcing every caller to check a case that does not exist; narrowed.
- **Four sweeps touched this file and none of them saw it.** FALLBACK-5 made `mode: "display"` throw and left the editing modes beside it alone. ADR-201 made `getHTML()` throw because `""` cannot be told from an empty document — **the identical argument applies to `getValue()`, which was reading the textarea three methods above it.** FALLBACK-11 removed CodeMirror's equivalent silence from CodeEditor and FALLBACK-13 removed MarkdownRenderer's. Each sweep found the shape it was written to match. The existing suite installs a `MockVditor` in `beforeEach`, so **nothing was pinning the substitution** — it survived on nobody looking.
- **A comment in `runtime.ts` froze two counts that nothing re-derived.** `checkDataChangesRender` carried *"of the 97 migrated components, 80 have no glue file ... all thirteen mount fixtures pass"*, measured on 12 October. Both were stale within a week, which is the failure mode DEBT-DUI-6 exists to watch for. The gate already **prints** the live figures on every run, so the paragraph now points at the log line instead of restating it.
- **AGENTS.md held up a falsified blocker as the model of a good one.** The passage taught "state what you TRIED" using GraphMinimap's *"Throws without `options.graphCanvas`, and jsdom has no 2D context"* — testable, measured-sounding, and false in both halves. It now says that a testable blocker is still only a claim, and that re-measuring a deferral means re-reading the code it describes.

- **DEBT-TEST-1c settles: six stand-ins, each verified rather than trusted** (ADR-213). The entry asserted the remaining six were correct and nothing had checked since. Each was checked: `formdialog` **deletes** `showConfirmDialog` to prove a dirty form refuses rather than closing silently, `ribbonbuilder` stubs then deletes and asserts `toBeUndefined()`, `diagramengine` records what the engine handed the renderer, and the three `spinemap` cases plant factories that **throw** to prove the error propagates with its cause attached. **In every one the stub is the subject of the test** — which is the line against the defect the census was built for, where the pre-fix GraphToolbar suite asserted on values its own fake Toolbar produced.
- **A new `siblingStandIns` ceiling at 6, and it is deliberately not a target of zero.** Driving it down means deleting refusal tests, and those are what caught FALLBACK-1 through FALLBACK-14. It exists so the population cannot grow unobserved — which is how the GraphToolbar defect survived. Mutation-proven: planting one stand-in in an unrelated suite takes it to 7 and trips the gate. No test and no component changed.
- **DEBT-LAY-1 closes: four layouts no longer claim a capability they never had** (ADR-212). `contained` means "fill the parent instead of `document.body`", and the measurement settles the protocol question the entry held open: **Toolbar has one `document.body.appendChild`, Sidebar has two, and AnchorLayout, BorderLayout, BoxLayout and CardLayout have zero between them.** They always fill their parent, so the flag has nothing to decide. The field and the setter are deleted from all four.
- **Deleting it is what makes the protocol honest.** Every caller is duck-typed — `if (typeof child.setContained === "function")` — so a component that does not implement the method answers "absent" correctly, while one that implements it as a no-op answers "present" and lies. `unusedLocals` **305 to 301**, one per layout, independently confirming all four fields were unread.
- **This is a breaking public API removal and it is intended.** `setContained(value)` was in all four READMEs as "Set contained mode" and set nothing, so no behaviour changes — but a direct caller now gets a TypeError instead of silence. Pinned by `contained-protocol.test.ts`, which asserts the absence **and carries a control** asserting Toolbar still claims it, because without the control the assertion would pass against a codebase where nothing implements the protocol at all.
- **A test pinned the workaround as though it were an invariant, and CI caught it** (ADR-211). `sri-manifest.test.ts` asserted that `codemirror6` IS recorded as unhashable. Vendoring made that false, so the commit that REMOVED the limitation failed the suite, and the failure looked exactly like a regression. The assertion is now the real invariant — nothing sits in `unhashable` without a recorded reason — plus one that CodeMirror has left the third-party-CDN population entirely. **The miss was mine: I reported a passing unit count from a run that predated the manifest edit, and never re-read the result after it.**
- **DEBT-SEC-9 closes at zero: CodeMirror 6 is vendored** (ADR-211). Fourteen packages bundled into one self-contained 640 KB file served from this origin and hashed — **28 inputs, 0 external**, with the closure asserted from esbuild's metafile so the build refuses to publish an artifact that still resolves anything at run time. `cdnModuleSpecifiers` **67 to 0**. `unpinnedCdnRefs` **77 to 10**, a fall of 67 as a side effect, because the esm.sh URLs floated at major `@6` and were most of what that count measured.
- **The bundle publishes bare globals rather than a namespace, on purpose.** CodeEditor probes about thirty bare names, so a namespace would have left every consumer writing the same thirty lines of glue the CDN version needed — and that glue was 14 of the 67, in a README consumers copy. Trading unhashed-and-floating for hashed-and-verbose would have missed the point. The consumer path is now one tag.
- **The glue that README published was broken, and had been.** It assigned the bare name `history`. `window.history` is the browser's History object and a read-only accessor on `Window`, so the assignment **silently fails**, and `codeeditor.ts:828` then rejects it because it is an object rather than a function. **Anyone who followed that README had an editor with no undo history and no error explaining it.** `tests/codemirror-vendored.spec.ts` types, undoes, and asserts the text came back.
- **A hash in the documentation was decoration, and a mutation proved it.** Changing a published hash in a README did not fail `check-closure.mjs`: the gate was hash-first and silently skipped any integrity it did not recognise, so the only effect was the inspected count dropping by one. It now also asks the URL-first question — a tag pointing at a vendored asset must carry that asset's hash — and **immediately found two real defects**, where `CDN_CONTRACT.md` and `docs/CDN_INTEGRATION_GUIDE.md` handed consumers font-awesome tags with a `<placeholder>` where the hash belongs. Both now carry the published hash.
- **The `unhashable` key in `scripts/third-party-sri.json` is empty.** It held codemirror6 on the reasoning that integrity cannot attach to an import specifier. That was true and the conclusion did not follow — **the fix was never to hash a specifier, it was to stop having specifiers.** Its old note said a consumer could bundle CodeMirror or self-host and that "neither is something this repository can do on their behalf". Both were.
- **Still third-party at run time**, stated plainly: `guidedtour.html` loads driver.js from jsdelivr with a hash, and most demo pages load Google Fonts. Fonts are a population no count here covers.
- **DEBT-SEC-8 closes at its floor, and seven of its seventeen findings were a gate bug** (ADR-210). `cdnTagsIn` matched any `<script>` or `<link>` carrying a CDN host and demanded an integrity hash. **Seven were `rel="preconnect"` tags.** A preconnect opens a socket and fetches no bytes, so there is no body to hash and the HTML spec defines no `integrity` for it — the only way to "fix" one was to delete a performance hint. The filter now skips `preconnect` and `dns-prefetch` and keeps `preload` and `modulepreload`, which fetch and do accept `integrity`. `thirdPartyTagsWithoutSri` **17 to 10**, the floor the entry set for itself, the remaining ten being dated `specs/*.prd.md` history.
- **Two of those seven were dead hints as well.** `conversation` and `markdowneditor` preconnected to `unpkg.com` and loaded nothing from it after ADR-190 and ADR-199 moved dompurify and vditor to `/lib/`. Deleted — a hint to a host you no longer use costs a connection and tells that host a visitor arrived.
- **DEBT-SEC-9 opens on 67 ES-module specifiers that no gate could see.** `thirdPartyTagsWithoutSri` matches TAGS, and a dynamic `import()` of an esm.sh URL is not a tag. 67 occurrences across five files, 14 distinct CodeMirror packages. **This was not a discovery** — DEBT-SEC-8's prose and the `unhashable` key in `scripts/third-party-sri.json` both described them accurately, including the floating major `@6`. What was missing was a number, so nothing would have noticed the population growing. Fourth count in `audit-counts.mjs` named for one population and measuring another.
- **No shipped component loads from a CDN at runtime**, verified across every `components/*/*.ts`. `codeeditor.ts:161` states the host page supplies CodeMirror, and the component throws a literate error when the globals are absent. The exposure is in what this repository demonstrates and documents — including `components/codeeditor/README.md`, which hands consumers 14 unhashed, major-pinned imports.
- **The ceiling holds rather than drives to zero.** A dynamic import takes no integrity argument and a static specifier has no attributes, but import maps DO define an `integrity` key, so this is a support problem and not an impossibility. Vendoring 14 CodeMirror packages into `dist/lib` would remove the CDN, the unhashed load and the floating major together, at a real bundle cost — recorded for decision rather than taken.
- **DEBT-TV-1 is settled rather than fixed, because the measurement inverted the question** (ADR-209). The entry read as a defect with the fix withheld: an inline rename field that asked for 22px and rendered at 29.72px. Then the row was measured. **A tree row is 30px**, so the field FILLS its row, and the row is 120px both before and during a rename — **no layout shift at all**. A 22px input would be SMALLER than the row it sits in, floating with slack above and below. Screenshots of both states were put in front of the owner and the difference is barely visible, which is the answer: **the thing that was never built is the thing that was not needed.** The 22px target is retired rather than implemented, and the dead declaration that claimed it stays deleted.
- **The settlement is enforced, not just written down.** `treeviewRenameInput_FillsItsRowAndDoesNotShiftIt` asserts the input is within a pixel of its row and that renaming moves nothing. Reinstating `height: 22px` fails it. A past declaration asking for a number is not evidence the number is right, so the test pins the relationship rather than the figure.
- **IMP-1 closes at zero, and the visual check it waited for was never needed** (ADR-209). "Specificity changes are visual" is true of colour and spacing judgements and **false of a computed value** — the cascade resolves to a number, and `getComputedStyle` reports it. Five Playwright assertions in `tests/important-removal.spec.ts` replaced the screenshot suite this repository does not have, and **all five declarations turned out to be beating nothing**. graphcanvas's 4 were supposedly losing to `.gc-node:hover rect` at (0,2,1): that rule sets `stroke-width` to the same 2.5 and never sets `stroke`, and the only other source is a presentation attribute from `svgCreate`, which loses to any CSS rule. ribbon's 1 duplicated the inline `display: flex` that `ribbon.ts:2647` sets on content appended to `rootEl`.
- **treeview needed no specificity change at all, and a mutation is how I know.** An element compound went in first on the arithmetic that (0,1,1) beats `.form-control-sm` at (0,1,0). Reverting it moved no computed value, because this stylesheet loads after Bootstrap and source order had already settled the tie, so the compound came out. **A specificity argument is a guess with notation on it until something measures it.**
- **`height: 22px` on the inline rename field has never applied** (DEBT-TV-1). Bootstrap's `.form-control-sm` sets `min-height: calc(1.5em + 0.5rem + 2px)`, and **`min-height` beats `height` at any specificity and with any keyword**. The field renders at 29.7188px and always did. The dead declaration is deleted and the intent is NOT restored, because a compact field needs `min-height` set too and that changes how renaming looks in every tree. Found while removing a keyword, not by looking for it.
- **The comment requirement is now counted rather than asserted.** ADR-208 added a rule to CODING_STYLE.md with about 40 declarations not following it and nothing checking. All 44 remaining declarations carry an `important-case: N` tag, held by a new `scssImportantUncommented` ceiling at zero. The helper is pinned by **seven tests including the Allman case**, and a mutation narrowing its search from the block to the line fails four of them.
- **54 declarations became 44.** `scssImportant` 108 → 103, `scssImportantComponents` 50 → 45, testBlocks floor 4976 → 4983. 5270 unit tests in 162 files, 32/32 structure checks.
- **IMP-1 was 29 unjustified `!important` in 8 files, and it is 5 in 2** (ADR-208). No code changed and no ratchet moved. The owner asked whether `markdowneditor` and `chartpanel` were overriding external components before the entry called their declarations unnecessary. They were, and checking it pulled the classification apart. **The old split sorted by whether a comment sat near the declaration**, which measures nothing — a comment records a justification and does not create one. All 17 of markdowneditor's target `.vditor*` and are the same Vditor override, yet 11 read as defects for want of a sentence above them. Sorted by what each one OVERRIDES, the 54 real declarations in 18 files are 11 in `prefers-reduced-motion`, 24 against a third-party stylesheet, 9 against an inline style, 5 against a Bootstrap component class, and **5 in-house specificity bugs**. **Twelve have exactly one legal spelling**: Bootstrap emits `.bg-light` and `.text-muted` with `!important` already, and no selector at any specificity outranks an inline declaration. Three more — stacklayout's pair and splitlayout's one — are `!important` or deleted rather than `!important` or broken, because there the inline value equals the rule and a plain version would be permanently shadowed.
- **The entry's own worked example would have shipped a regression.** It said stacklayout's pair "would be settled by `.stacklayout-panel.stacklayout-panel-collapsed`". `stacklayout.ts:420-422` sets `flexGrow`, `flexShrink` and `flexBasis` **inline** on `wrapperEl` and `:500` adds that class to the same element. ### Fixed — a component that cannot read now refuses rather than fabricating (ADR-148)

Twelve sites across seven components answered a read after failing to initialise, returning a plausible value a host would then persist over the user's own. This is the shape that destroyed unrecoverable production data in a consuming app on 2026-10-03.
